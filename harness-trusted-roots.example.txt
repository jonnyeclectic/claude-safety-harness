# Trusted roots for the bypass safety harness.
#
# Copy this file to  ~/.claude/harness-trusted-roots.txt  and edit it.
#
# Directories listed here are treated as part of your workspace: the harness
# will NOT prompt for edits or file-mutations that land in them, even though
# they're outside the current session's working directory. One path or glob
# per line; blank lines and lines starting with # are ignored.
#
# The current session's working directory is ALWAYS trusted automatically, so
# you only need to list SIBLING checkouts / worktrees / related repos.
#
# This relaxes ONLY the out-of-workdir location gate. These still apply,
# trusted root or not:
#   deny  -> rm -rf /, dd/mkfs to a device, fork bomb, chmod -R on /
#   ask   -> sudo, force-push, git reset --hard <sha|HEAD~N>, curl|bash
#
# Globs allowed: * ? []    e.g. ~/work-*  matches ~/work-loop, ~/work-tilde
#
# WON'T WORK: Claude Code hard-denies bash writes to its own config surface
# (~/.claude/skills, hooks, agents, commands, plugins, settings.json, ... and a
# project's .claude/ equivalents) and that deny beats allowWrite, so listing one
# here does nothing at the kernel level. Deliberate: a skills dir you can write
# is a way for a hijacked subprocess to author instructions for your next
# session. Run skill/plugin installers from a normal terminal instead.
# ~/.claude/plans and ~/.claude/projects/*/memory are output, not config, and DO
# work as trusted roots. See "What trusted roots can't reach" in the README.
